Библиотека PIL. Рисование

Кисти, краски, два скрипта

Давайте начистоту: мы живем в эпоху визуальной информации. Каждую секунду в социальные сети (разрешённые и запрещённые) загружаются тысячи фотографий, каждый день в Pinterest люди сохраняют 3 миллиарда пинов! И знаете что? Кто-то же всё это обрабатывает и создаёт.

Сегодня и мы займёмся созданием изображений с помощью Python. Мы выбрали тему с картинками не только из-за того, что фотографии мегапопулярны, а полупрофессиональное комьюнити фотографов — одно из самых больших на планете, но и ещё по нескольким причинам:

Видео — это картинки по очереди. Любые фокусы — фильтры, маски, хромакей — сводятся к работе с отдельными кадрами, то есть картинками. Освоим работу с изображениями — поймём и видео.

Модель хранения изображений в памяти компьютера простая и математичная — это таблица чисел. Прямо мечта для практики: списки, циклы, кортежи — всё как мы любим.

В 1961 году программист Рассел Кирш сканировал первую цифровую фотографию — со своим сыном. Разрешение 176 × 176 пикселей. Сейчас бюджетный смартфон делает фотографии в сотни раз качественнее.

Альтернатива — векторная графика (кривые, линии и формулы). Для неё в Python есть библиотеки вроде gizeh/Cairo. Если интересно, можете копнуть самостоятельно: там всё про геометрию и трансформации. Векторные изображения можно бесконечно масштабировать, но с мелкими деталями там всё не очень.

Итак, изображение можно моделировать списком списков — двумерной таблицей, в которой лежат цвета. Осталось только подумать, как именно кодировать цвета.

Опыт работы со строками, где каждому символу соответствует свой код, должен подсказывать вам, что и с изображениями должно быть так же. Мы можем пронумеровать некоторое количество цветов и указывать их номера в нашем списке списков. Совокупность выбранных цветов будет называться палитрой.

В итоге нам нужен способ преобразования цветов в целые числа. Мы воспользуемся одной из самых популярных моделей представления цвета — RGB (Red, Green, Blue).

В модели RGB каждый цвет представляется совокупностью трёх компонент: красной, синей и зелёной. Значение каждой компоненты лежит в диапазоне от 0 (минимум) до 255 (максимум), занимая 1 байт в памяти.

На самом деле модели хранения этих байтов в памяти Python и файле с картинкой бывают очень сложными — например, со сжатием. Однако мы будем работать с исходными, «чистыми» данными.

Итак, каждый цвет — совокупность трёх целых чисел (в Python её можно представить кортежем или списком). Например, (0, 0, 0) — чёрный цвет. Его яркость минимальна, оттенков нет.

(255, 255, 255) — белый, максимальная яркость.

(255, 0, 255) — очень насыщенный пурпурный (красный + синий).

(255, 255, 0) — ярко-жёлтый (красный + зеленый).

(100, 100, 100) — серый (три одинаковых компоненты всегда дают серый цвет, отличаются только оттенки).

Сумма этих трёх числовых компонент говорит о яркости пикселя: чем сумма больше, тем пиксель кажется ярче. На самом деле и тут всё сложнее, чем кажется: яркость каждой компоненты для глаза не одинакова, однако примем это упрощение.

Красный, зелёный и синий выбраны в качестве основных цветов не случайно. Дело в особенностях нашего зрения! В сетчатке глаза есть три типа колбочек, чувствительных к разным диапазонам света:

L-колбочки — длинные волны (красный).

M-колбочки — средние волны (зелёный).

S-колбочки — короткие волны (синий).

Мозг комбинирует сигналы от этих колбочек, создавая всё многообразие цветов, которые мы видим.

Кстати, если мы сильно увеличим матрицу смартфона или монитора, который светит чистым белым светом, увидим что-то вроде этого:

В качестве микроэксперимента: посмотрите на пиксели телефона через капельку воды (получится простейшая линза). Или выньте линзочку из лазерной указки (аккуратно!) и приложите к камере — получится микроскоп, в котором RGB-пиксели экрана другого смартфона видны как на ладони.

Итак, для нас изображение — список списков, элементы которого — кортежи цвета.

Легко заметить, что в нашей модели всего 256 × 256 × 256 = 16777216 разных цветов. Этого вполне достаточно, чтобы человеческий глаз не замечал дискретности (конечного числа оттенков) цветовой модели.

У Яндекса есть специальный барабан, который позволяет знакомиться c оттенками цвета, подбирать их и узнавать их коды.

🛒 В магазин за инструментами

Для работы с изображениями мы будем использовать библиотеку PIL (Python image library), а точнее её модификацию под названием Pillow.

Pillow не входит в стандартную поставку Python, поэтому нам необходимо её установить дополнительно из PyPI.

PyPI (The Python Package Index) — центральный репозиторий (хранилище) модулей для языка программирования Python. Он как PlayMarket для Android, AppStore для iPhone или CPAN для Perl.

На текущий момент количество разнообразных модулей в PyPI уже в районе 700 000, поэтому не будет преувеличением сказать, что у Python на все случаи жизни есть нужная библиотека.

Для установки библиотек из PyPI (и из других хранилищ библиотек) используется консольная утилита pip.

Чтобы установить пакет, нужно выполнить команду pip install <Имя модуля>. Пакет будет скачан с PyPI и установлен.

Для того, чтобы установить PIL давайте откроем терминал в VS Code (или в той среде, которой вы пользуетесь), вызовем терминал (если он ещё не открыт) через меню (Terminal -> New terminal) или горячей клавишей (ctrl + shift + `). Открывшейся тьме командной строки скормим команду:

Итак, приступим.

Для работы нам потребуется файл с изображением (мы возьмём для примера картинку с совой и питоном, которая была выше), который нужно сохранить в тот же каталог, где будут лежать программы по его обработке.

В результате в папке появится ещё одна картинка. В нашем случае — более «ночной» вариант исходного изображения.

Теперь чуть подробнее о том, что происходит. Во-первых, для работы с изображением нам нужен модуль Image, который находится в библиотеке PIL (пишется большими буквами).

Мы открываем изображение с диска функцией .open() модуля Image. В качестве параметра указывается или абсолютный путь к файлу, или просто имя файла, если файл размещён в том же каталоге, что и сама программа. В результате получаем объект-картинку, с которой будем работать дальше.

Метод .load() загружает двумерный список пикселей этого изображения в переменную pixels, где для каждого пикселя хранится кортеж — цвет пикселя в палитре RGB.

Обратите внимание: pixels устроен так, что индексация в нём идет кортежами, поэтому здесь запись pixels[i, j], а не pixels[i][j], что, возможно, было бы удобнее и привычнее. Это особенность библиотеки: создателям показалось, что так будет архитектурно уместнее.

С помощью атрибута .size (не метода!) объекта-картинки мы можем получить размер изображения, который хранится в виде кортежа: сначала ширина, потом высота в пикселях, что соответствует размерности pixels.

Далее переберём все элементы pixels двумя циклами for и для каждого элемента получим значение трёх компонент цвета. Запишем в массив pixels эти значения обратно, но немного изменив порядок.

🎨 Примитивное видение

С помощью библиотеки PIL мы можем не только изменять существующие изображения, но и создавать новые.

Для этого используется функция Image.new(), которая принимает тип палитры, кортеж с размером нового изображения и цвет, которым будет залито это изображение. Если цвет не указать, изображение будет чёрным.

Мы договорились использовать палитру RGB, но есть ещё несколько, например: CMYK (для печати), RGBA (RGB с прозрачностью).

Создавать однотонные изображения не особенно интересно, поэтому давайте посмотрим, какие возможности даёт библиотека PIL, если нам хочется что-то нарисовать.

Для этого нам понадобится объект Draw из модуля PIL.ImageDraw. У этого объекта есть много инструментов для создания графических примитивов: прямых, кривых, точек, прямоугольников, дуг и т. д.

Оси координат при работе с изображениями выходят из левого верхнего угла (0,0): ось x идёт вправо, y — вниз. Правый нижний угол — (width, height).
