Известный тип

Python — язык с динамической типизацией. Это значит, что интерпретатор не заставляет вас заранее объявлять типы переменных. Казалось бы, праздник жизни! Но... Чем больше проект, тем сильнее хочется в какой‑то момент понять: а что сюда вообще передаётся? И что обратно вылетает из функции?

Идеально — чтобы это понимала и IDE, и линтер, и будущий «вы», который откроет этот код через полгода.

Для улучшения читаемости и упрощения поддержки кода есть несколько приёмов:

Комментарии. Мы про них уже неоднократно говорили, но сегодня рассмотрим специальный тип комментария — docstring.

Аннотации типов. Специальные подсказки для среды разработки и программистов про то, какого типа должна быть переменная.

🩺 Доктор, что со мной?

Докстринг — это тройные кавычки сразу после объявления функции/класса/модуля. Он попадает в .__doc__, виден в help() и из IDE. Главное правило: пишите для человека, а не для формальной проверки.

Существует минимум три общепринятых стиля для докстринга:

Google — блоки с аргументами, возвращаемым значением и исключениями (про исключения поговорим уже совсем скоро) отделяются табуляцией.

Numpy — блоки с описанием параметров (аргументов) возвращаемого значения и возможных исключений отделяются некоторым количеством дефисов.

reST — сначала пишется, что делает функция, потом через двоеточия оформляются параметры, возвращаемое значение и возможные исключения.

Выберите один стиль и держитесь его. Смешивание стилей — как носки разного цвета: чаще раздражает, чем выглядит хорошо.

🧐 Не читай мне аннотации

Представьте, что вы делаете заказ в ресторане. Без аннотаций типов — это как сказать «принесите еды». С аннотациями — «принесите пиццу Пепперони, размер XXXL, с тройным сыром».

В Python аннотации — это просто подсказки. Интерпретатор не проверяет их в рантайме (если вы сами не попросите). Синтаксис максимально простой:

age: int = 16 # Возраст как целое число

name: str = "Петя" # Имя — строка

price: float = 19.99

is_active: bool = True

Аннотации принято указывать и для параметров функций, и для возвращаемых значений.

Более сложные аннотации можно писать с помощью модуля typing. До Python 3.9, если вам хотелось указать, что тип значения — список, множество, кортеж или словарь, приходилось импортировать оттуда List, Set, Tuple, Dict соответственно. Сейчас можно писать более привычно:

users: list[str] = ["Петя", "Маша", "Гриша"]

index: dict[str, int] = {"Петя": 0, "Маша": 1}

unique: set[int] = {1, 2, 3}

coords: tuple[float, float] = (55.7522, 37.6156) # Широта, долгота

tail: tuple[int, ...] = (1, 2, 3, 4, 5)

Главные правила сегодняшнего урока:

Аннотации типов — помогают сузить круг подозреваемых типов при вызове функций и анализе возвращаемого значения.

docstring — это экономия времени на поддержке кода для будущих вас или ваших коллег.

Правильные аннотации делают ваш код значительно лучше и читаемее.

Первые программисты писали документацию на бумаге и передавали друг другу. Теперь у вас есть Python с его крутыми фичами — используйте эту силу!

P. S. Аннотации — это как наклейки на банки на кухне. Непосредственно в приготовлении блюда не участвуют, но находить ингредиенты становится вдвое легче.
